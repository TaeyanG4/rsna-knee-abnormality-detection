# 누적 작업·handoff 판단 감사 — 2026-10-03

판정 기준: 당시 합리적인 탐색이었는지, 실제 관측이 무엇을 입증했는지, 다음 확대가 정당했는지를 구분한다. 결론은 **기반 구축·0.943 재현·소규모 학습 탐색은 타당했지만, 평가의 독립성과 일부 성능 원인 해석이 부족했고 다음 확대 계획은 수정해야 한다**는 것이다.

범위: STATE·월별 색인·관련 handoff의 기준본/검증/원격/라벨/입력 결정과 최근 모델 summary·현재 코드. 앱 전체 코드, 모든 과거 EXP, 전체 DICOM을 전수 재감사한 것은 아니다. 과거 handoff는 당시 관측으로 보존하며 현재 결정은 [실행 계획](route-to-first-2026-10-03.md)과 ADR0003/0004를 따른다.

## 12:12 KST · handoff 작업 과정 재검토

이전 감사도 재검토했다. **탐색 착수와 결과 보존은 합리적이었지만, 성능 판단의 독립성을 확인하기 전에 다음 변형으로 확대했던 순서는 타당하지 않았다.** 관련 handoff·현재 소스·기존 산출물을 대조했고 학습은 재실행하지 않았다. 이번 [재계산·파일 hash](../handoffs/evidence/2026-10/2026-10-03-process-review/verification.json)와 [검사 스크립트](../handoffs/evidence/2026-10/2026-10-03-process-review/verify_process.py), [변경 전 문서](../handoffs/archive/snapshots/2026-10-03-process-review/manifest.json)를 보존했다.

1. **R2의 평가 대상도 변경됐다.** [raptor_train.py](../../training/src/raptor_train.py)의 `all_labels`는 학습/검증에 같은 혼합 CSV를 사용하고, [raptor_common.py](../../training/src/raptor_common.py)의 `macro_auc`는 soft label을 반올림한다. 동일4,345 study×12개 중 **1,400개(2.69%)**의 평가 양·음성이 바뀐다. Contusion 양성661→891, Lateral Meniscus585→780, Fracture159→223. 기존 F0 best 예측으로 직접 재계산하면 혼합라벨 AUC0.914552, 원라벨0.897046이다. 이 수치 차이는 서로 다른 평가대상에서 나온 것이며 누출의 크기가 아니다. 당시 원라벨 재채점은 올바른 보완이었지만 이미 혼합라벨로 선택한 epoch를 되돌리지는 못한다. 재선택 시 얼마나 달라지는지는 미측정이다.
2. **간접 누출 지적은 유지한다.** teacher/student15개 summary의 split hash가 같고, 혼합 manifest는 전체5fold teacher OOF를 가리킨다. 학생F0의 학습자료F1~4 라벨을 만든 다른-fold teacher들이 F0를 학습한 구조다. 원라벨 재채점·bootstrap으로 제거되지 않는다. 다만 누출 기여량이나 private 영향은 측정하지 않았으므로 ‘R2 무효/폐기’나 ‘테스트 누출’ 판정으로 확대하지 않는다.
3. **‘라벨 교정 효과’와 loss 변화가 섞였다.** teacher는 `pos_weight`가 있는 BCE를 쓰므로 sigmoid를 보정된 정답확률로 가정할 수 없다. [label_mix.py](../../training/src/label_mix.py)는 이를 raw 값으로 혼합하고 학생은 바뀐 라벨 평균으로 `pos_weight`를 다시 계산한다. 새 정보와 loss 가중 변화가 함께 작용한다. 결함이나 성능 저하가 확인된 것은 아니지만, 효과 원인을 설명하려면 가중치를 고정한 대조 등이 필요하다.
4. **순차 실행과 연구 gate는 달랐다.** [gpu_queue.py](../../tools/gpu_queue.py)는 종료 marker만 확인하며 AUC·누출·parity를 판정하지 않는다. 실제 R1/R2변형 계획은 다음 작업을 미리 연결했고, R2변형은 `continue_on_failure=true`여서 06:10~06:13 같은 GPU 오류가4건 연속 발생했다. CPU/환경 실패와 연구 가설 실패를 구분하고, 다음 단계 확대는 별도 결과 검토 뒤 등록해야 한다. 같은 레시피의 필요한 fold를 묶는 것 자체가 잘못은 아니다. 06:00 인계의 ‘변형5개 미실행’은 정확히는 **완료 결과 없음**이다.4개 실패 이력이 있고 A70 F0은 재시작 후 epoch0까지 진행하다 중단됐다.
5. **실행 당시 재현성 증거에 공백이 있다.** 확인한 로컬 `job.json`과 원격 `run_remote.json`에는 실행 코드 hash가 없고, remote kernel의 dataset 참조도 버전 없는 slug다. 학습라벨·split hash는 남아 있으나 현재 코드 hash로 학습 당시 코드까지 동일했다고 증명할 수 없다. 다음 실행부터 실제 코드/bundle·데이터셋 버전·가중치/라벨/split hash를 연결해야 한다. 이번 확인만으로 과거 원격 버전을 복구할 수 없다고 단정하지 않는다.

반대 근거도 확인했다. 15개 모델의 기존 best/SWA 예측30개는 각 fold의869 UID와 모두 일치했고, 06:00 비교대상9개 summary는 best를 선택했다. 따라서 이번 R2 비교를 UID 누락이나 Gold의 best/SWA 혼용 때문에 잘못됐다고 볼 근거는 없다. 다만 `fold_compare`의 UID 교집합·SWA 부재 시 best fallback은 향후 비교에서 명시 확인해야 한다.

11:46의 수정 방향은 대체로 타당하다. **D01의90:10은 준비된 모델을 연결하는 탐색 제안이며 최선이라는 증거가 없다.** P2의 weak-AUC +0.002는 보고서 라벨 예측력에 관한 운영 gate다. 미달을 임상 라벨 교정 자체의 무효로 해석하지 않는다. 다음 순서는 평가라벨/teacher 계보/epoch 선택 분리 → 작은 고정 대조 → 결과 검토 후 확대다. 공개 LB 비율 탐색을 다시 늘리는 것으로 평가 문제를 대신하지 않는다.

## 기록 해석에서 주의할 점

**문서의 요구와 도구 구현을 구분한다.** 현재 label_mix는 UID중복·Gold혼입·95% coverage를 검사하지만 teacher의 학습 fold 계보를 검사하지 않는다. raptor_report/fold_compare의 bootstrap도 report-group이 아니라 study 단위다. runbook의 ‘깨끗한 OOF 거부 검사’ 표현을 정정하고 필요한 보완은 미구현으로 표시했다. aggregate Gold AUC가 비슷한 것 역시 입력/예측 parity의 충분조건은 아니다.
**같은 실험 이름이라도 checkpoint가 다르면 수치가 다르다.** EXP060 F0 summary 선택값0.896286은 SWA, model_best의0.895952와 다르다. ResNet34의 과거 합산0.8702와 오전 best-only 재채점0.866471도 선택 정책을 확인해야 한다. 이 차이를 무조건 잘못된 기록이나 모델 성능 악화로 해석하지 않는다. 새 비교는 checkpoint 집합을 고정하고 기록한다.

**현재 fold 학습에서 Gold를 직접 epoch 선택에 썼다고 단정하지 않는다.** 실제 args는 select=oof다. 다만 코드가 Gold를 매 epoch 평가/출력하고, full-data에서 OOF가 없으면 Gold로 선택하는 경로가 존재한다. 전자는 사람의 반복 의사결정에 노출될 위험, 후자는 이번 확인 대상21개에서 사용을 확인하지 않은 위험 경로다. summary의 gold_once 명칭만으로 실제1회 평가라고 믿으면 안 된다.

**경계/결측 창 발견은 공개 모델을 즉시 고칠 이유가 아니다.** 공개 가중치가 그 전처리로 학습됐다면 입력 변경만으로 parity를 깨뜨릴 수 있다. 기존 arm은 보존하고 자체 재학습의 통제 비교로 다룬다.

**자원·도구가 갖춰졌다는 사실과 상위권 성능은 다르다.** 데이터·앱·캐시·원격 작업을 모두 낭비라고 볼 근거는 없다. 지금부터는 준비된 checkpoint를 실전 추론/검증으로 연결하는 쪽에 시간을 더 써야 한다. 반복 조사와 거대한 사전 정비가 다음 유효한 실험을 계속 미루지 않도록 한다.

## 실행 방향에 미치는 영향

1. 기존 산출물은 보존한다.0.943 기준본, R2를 포함한 모델, 원본/캐시/라벨을 폐기할 이유는 없다.
2. R2의 효과 확정과 대량 확장은 철회한다. 기존 R2 고정10% 추가 후보는 **탐색**으로 준비하고, 독립성을 보완한 outer2개 대조를 별도로 수행한다.
3. public LB 최고점·Gold58·기존 weak CV 중 하나만으로 결론내리지 않는다. 제출 전 고정 가설/비율, 내부·domain 안정성, 실행 품질을 함께 본다.
4. 장시간 작업은 작업ID/ETA/로그와 완료 확인 예약을 남기고 반환한다. 실제 완료 후에만 허가된 다음 단계를 이어간다. 자세한 절차는 [도구 runbook](../runbooks/tools.md).
