# MCL 보고서 120건 가림 검토 — 사전 규칙 v1.0

2026-10-03. **목표는 MCL 감독 정의를 보고서에서 일관되게 추출할 수 있는지 확인하는 것이다.** 새 모델 성적 검증·의사의 영상 판정·임상 정답 생성이 아니다. 원래 라벨·가중치·학습은 변경하지 않는다. [앞선 감사](mcl-label-definition-audit-2026-10-03.md)의 25건은 규칙 개발에 이미 노출된 예시다.

## 고정 범위와 표본

- train에서 Gold58, Gold 보고서중복 격리, EXP078의 추가 손상 2건을 제외한다. 앞서 직접 검토한 25건뿐 아니라 이전 오류 상위10/검토목록에 들어간 보고서도 보수적으로 제외한다. 총 67 study와 같은 보고서그룹을 제외하여 새 문맥을 읽는다.
- 동일 보고서그룹과 공백 정규화 원문 중복은 각각 최대 1건만 선택한다. 이는 환자·영상 독립성을 보장하지 않는다. 이전 모델이 학습한 개발 코호트라는 사실은 남는다.
- 고정 seed `mcl-report-review-2026-10-03-v1`와 SHA256 정렬을 사용한다. 검색상 고도/완전파열 12건 → 저등급/과거손상 30건 → 불명확 grade II/부분파열 20건 → 두 소스의 이진 불일치 30건 → 부정문 대조 14건 → 미언급 대조 14건 순서로 상호배타 층을 만든다. 층은 검색 가설이지 정답이 아니다. 부족한 층을 임의로 보충하지 않는다.
- 각 층의 추첨과 별도의 hash로 전체 순서를 섞은 뒤 익명 ID를 붙인다. 첫 20개 ID를 pilot으로 고정한다. 보고서를 본 뒤 쉬운 예시로 교체하거나 pilot 구성을 조정하지 않는다.
- 다국어 원문을 보존한다. 영어만 선별하지 않는다. 언어 이해가 불충분하면 검토 필요로 남긴다. 층화 목적표본의 판단 분포를 전체 오류율·유병률로 해석하지 않는다.

## 판정자 접근과 파일

도구: [mcl_review_packet.py](../../tools/mcl_review_packet.py). 근거 디렉터리: `docs/handoffs/evidence/2026-10/2026-10-03-mcl-review/`.

판정 때 읽을 파일은 `packet.jsonl` 또는 `pilot20.jsonl`과 `annotation_schema.json`, 이 규칙뿐이다. 판정 패킷의 각 행은 **익명 case_id와 전체 Report 두 필드만** 가진다. 예측·기존 라벨·소스명·study UID·fold·선택층을 싣지 않는다.

`sealed/mapping.jsonl`과 `sealed/selection_manifest.json`은 재현·감사를 위한 별도 파일이며 **판정 중 열지 않는다**. sealed는 접근 관례이지 암호화/접근제어가 아니다. 제작자가 데이터 소스·전체 층화 설계를 알고 있다는 한계와 이전 개발 예시 노출을 명시한다. 결과와 매핑을 대조하려면 pilot 판정 파일과 hash를 먼저 동결하고 별도 분석으로 수행한다. 이 작업에서는 대조하지 않는다.

## 원문에서 기록할 항목

판정은 study 전체를 바로 이진화하지 않고 구성요소별 주장부터 작성한다. 각 주장은 MCL/표층/심층/해부학 불명, 위치, 소견, assertion, 중증도, 시점, 섬유 단절, 부종을 별도로 기록한다. 다른 ACL/LCL/반월상연골/retinaculum의 소견을 MCL에 옮기지 않는다.

- 중증도: `normal`, `low_grade`, `high_grade_partial`, `complete`, `partial_unspecified`, `grade_II_unspecified`, `unspecified`.
- 시점: `acute`, `chronic_remote_healed`, `acute_on_chronic`, `unspecified`. 검사 날짜·부종만으로 급성을 추정하지 않는다.
- assertion: `affirmed`, `negated`, `uncertain`, `historical`, `conditional`. “cannot exclude”, “suspected”를 확정 소견으로 바꾸지 않는다.
- 섬유 단절·부종: `present`, `absent`, `uncertain`, `not_reported`. 미기재와 명시적 부재를 구분한다. 명시적 완전파열은 섬유 단절을 기술한 것으로 해석할 수 있으나 부종을 자동 추정하지 않는다.
- 원문 evidence는 Python 문자열 기준 0-based `[start,end)`와 **정확히 일치하는 quote**를 보존한다. 해부학·부정·시점의 범위가 보이는 구절을 쓰고 필요하면 여러 span을 기록한다. 번역·설명은 별도 note/rationale에 쓴다. 원문 quote 안에 생략부호를 삽입하지 않는다.
- 언어·언어 확신도·재검토 필요·동일 구성요소의 직접 모순을 기록한다. Findings와 impression이 모순되면 자동으로 한쪽을 우선하지 않는다.

## 최종 텍스트 판정 규칙

`report_positive_candidate`: **명시적으로 급성인 고도 부분파열 또는 완전파열**이 MCL의 어느 구성요소에 확정적으로 기술되어 있고, 그 주장과 섬유 단절/부종의 명시적 부재가 충돌하지 않을 때다. “acute complete tear”처럼 진단 자체가 명시되면 부종 세부 기재가 없어도 후보로 기록하되 `not_reported`를 남긴다. 이는 대회 영상 정답 확정이 아니다. “high-grade tear”만 있고 급성이 명시되지 않으면 이 보수적 규칙에서는 `unknown`이다.

`report_negative_candidate`: 명시적 정상/intact, 명시적 low-grade, 또는 만성·과거·치유 소견만 있으며, 다른 구성요소의 잠재적 고도 급성 손상이나 미해결 주장이 없을 때다. 음성 근거를 따로 선택한다. “no complete rupture”만으로 모든 고도 부분파열까지 음성화하지 않는다.

`unknown`: 수식 없는 partial tear/grade II, 급성이 불명인 고도 손상, 급성 부분의 중증도가 불명인 acute-on-chronic, 애매한 표현, 동일 구성요소 모순, 해부학 범위 불명 등을 포함한다. 원문에서는 low grade라고 명시된 “low grade II”는 low-grade로 기록한다. **low-grade 단어가 다른 구성요소의 명시적 고도 급성 파열을 덮어쓰면 안 된다.**

`not_mentioned`: MCL 및 그것을 포함하는 측부인대 평가가 보고서에 없다. 정상이라는 의미가 아니다. components는 빈 배열이다. `uninterpretable`: 언어/문맥을 해석할 수 없다. 필요한 구간과 이유를 남기며 기존 라벨을 참고해 채우지 않는다.

양성 후보가 있더라도 같은 구성요소에 직접 모순이 있으면 `unknown`으로 보낸다. 불명확한 고도 여부를 임의 음성으로 낮추거나 다수결로 해결하지 않는다. 제외 후보와 양성 후보가 서로 다른 구성요소에 있을 때는 양성 후보를 보존한다.

## Pilot과 변경 규칙

첫 20건을 한 번 판정하고 exact quote·schema·구성요소/최종판정의 기계적 일관성을 검사한다. 검사 통과는 해석의 임상적 정확성을 뜻하지 않는다. 가린 기존 라벨/예측과의 일치율은 계산하지 않는다.

규칙/스키마 수정이 필요하면 v1.0과 첫 판정을 보존하고 수정 이유·시각·새 버전으로 재판정한다. 유리한 결과를 얻기 위해 정의를 바꾸지 않는다. pilot을 나머지 100건과 합칠 때도 개발 판정임을 유지한다. 추후 다른 판정자/의사 영상 검토가 있으면 그 역할과 독립성을 별도로 기록한다.

시간 기록은 CPU 패킷 생성·도구검증, 실제 agent 판정 벽시계 시간, 사람 검토 예상치를 구분한다. 앞선 1–3시간은 120건의 **사람 검토 작업량 추정**이며 이번 agent 작업의 실측이나 임상 전문가 판정 시간 보증이 아니다. 새 학습·자동 라벨 반영은 이 프로토콜 범위에 없다.
