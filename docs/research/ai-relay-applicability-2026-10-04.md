## 3. 권장 운영안: 실험 담당자 A + 교차 검토자 B

**우리 프로젝트에 대한 제안이다. 원문에서 확인된 고정 운영 방식은 아니며 실제 역할 배정·규칙 변경·실행은 하지 않았다.** 원문의 계획·구현·검토 사실은8절에 따로 기록했다. 이전의 설계/구현을 제품별로 고정하는 제안보다, 한 실험의 질문부터 결과까지 책임지는 담당자와 별도 검토자가 현재 프로젝트에 적합하다고 판단한다.

A는 아이디어·계획·구현·실행·기록을 끝까지 맡는다. B는 비용이 큰 실행 전에 설계를 검토하고, 실행 후 채택 판단 전에 코드·산출물·해석을 검토한다. 예를 들어 Claude가A,Codex가B일 수 있고 반대로도 가능하다. 기존에 해당 코드를 담당하는 쪽을A로 정하고 다음 실험에서는 역할을 바꿀 수 있다. 역할은 실험 시작 전에 고정해 중간 책임 공백을 피한다.

1. **A가 가설과 최소 실험을 정한다.** 우선 현재 상태·누적 결정·완료 계약을 확인한다. 전략 선택 시3~5개 대안을 근거·비용·불확실성으로 비교하고 다음 실행 하나를 정한다. 실험 문서에는 문제/가설, 기준 스택과 hash, 바꿀 요소 하나, 검증 계약, 예산, 확대/보류/중단 조건, 재사용할 결과를 짧게 적는다.
2. **B가 실행 전 설계를 검토한다.** 비교 기준이 질문에 맞는지, patient/teacher/backbone 노출과 라벨·fold·test입력 조건이 타당한지, 같은 실험을 반복하는지, 결과를 어떻게 판정할지를 확인한다. 새 분할·라벨·teacher·평가기·stacking·제출 경로처럼 결론을 무효화할 수 있는 변경과 큰GPU지출은 실행 전에 검토한다. 필요한 경우 critical code도 학습 전에 본다. 아이디어의 성공을 미리 증명하라는 요구가 아니라, 실험이 질문에 답할 수 있게 만드는 검토다. 근거가 약한 새 가설도 값싼 판별 실험이 가능하면 열어둔다.
3. **A가 구현·실행·기록한다.** 새 코드의 작은 확인 후 기존 gpu_job/queue와 예산에 따라 진행한다. 원본·완료산출물은 보존하고 새 버전/실행ID를 쓴다. 설계가 바뀌면 달라진 항목만 다시 검토한다. 같은 파일을A/B가 동시에 수정하지 않고 로컬GPU실행은 한 담당자만 한다. 실험 문서에 source/config/weights hash, 정확 명령·로그·receipt·결과와 실패를 연결한다.
4. **B가 결과와 주장을 검토한다.** 실제 실행한 설정이 계획과 같은지, parent/worker 성공·NaN/skip·12target·UID·계약이 맞는지, 같은 기준 스택과 비교했는지 확인한다. 소견 손실·조건부CI·비용을 포함해 개선/불확실/실패/보류를 구분한다. 검토만으로 독립 재현이라고 하지 않으며, 가능하면 저장 예측으로 핵심 지표를 별도 확인한다. 같은 완료 검사를 매번 반복하거나 모든 학습을 재실행하는 절차는 두지 않는다. 노출weak결과를 임상/private증거로 바꾸지 않는다.
5. **A가 판정과 다음 행동을 마무리한다.** B가 근거 있는 오류를 찾으면A가 수정한다. 애매한 결과는 그대로 보존하거나 예산이 정해진 다음 대조로 넘긴다. 합의 자체를 과학적 증거로 세지 않는다. 기존 승인 범위의 실행은 담당자가 진행하며 매번 사용자 승인 단계를 추가하지 않는다.

값싼CPU탐색·읽기전용조사·기존계약을 그대로 사용하는작업은A가먼저하고B가중요결과를검토해도된다. 다만작업이싸더라도새평가계약/누출위험변경이면사전검토대상이다. B가항상이중으로전체문맥을로드하거나단순대기중반복확인할필요는없다. A가긴학습을돌리는동안 B의독립자료조사/다음가설정리는가능하나새실행이나같은파일편집과구분한다.

문서는 늘리지 않는다. AGENTS는 역할·자원·검토 기준 같은 안정된 규칙, HANDOFF는 담당A/B·현재단계·다음행동·상세링크를 맡도록 제안한다. 기존 실험 문서 한 곳에 계획/실행결과/검토/최종판정을 둬 각 단계마다 별도MD를 만들지 않는다. 검토 의견의 원문을 별도파일로받더라도 담당자가요약/링크를한곳으로모으고중앙문서편집은한명만한다. 장기근거는기존decision-memory/runbooks/실험산출물로연결한다.

첫 적용 대상은 새로 선택되는 실험 하나다. RN3나기존보류작업을이제안만으로재개하지않는다. 이번 프로젝트에서 사전검토의 핵심 예시는‘B에RN을더하는질문인가,0.943anchor에더하는질문인가’이고, 사후검토에서는실제제출멤버/계산식이그질문에맞았는지를확인한다.

세션 운영의 기본은 **작업 단계에 맞춘 순차 인계**다. A계획→B사전검토→A구현/실행/기록→B결과검토로 진행하며 두 세션을 상시 동시에 일시킬 필요는 없다. GPU작업 중 독립적인B의검토/자료조사는선택적으로겹칠수있다. 토큰소진시다른쪽으로넘기는것은예비수단이며검토단계의대체가아니다. 전환전현재코드/계약·실행중job/로그·미완료·검토범위를남기고받는쪽이기존작업을회수해중복실행을막는다. 자동세션전환을구현했다는주장은아니다.

원문사실: 저자는댓글3531508에서‘At most there is one agent working at a time’이라고했고본문은세대별릴레이를설명한다. 댓글3531752에서새모델출시에따른담당교체를설명하지만토큰소진이교대원인이었다는기술은없다. 본문의helper조사/코드검토도존재하므로세부세션의동시실행일정까지복원한것은아니다.

## 4. 기록은 추가량보다 비교 대상을 정확히

별도 병렬 ledger를 먼저 만들기보다 기존 summary/manifest/receipt에 아래 항목이 있는지 확인하고 빠진 항목만 보완하는 편이 낫다. 이후 ledger가 필요하면 원본 기록에서 생성하는 색인으로 둔다.

| 기록 묶음 | 최소 내용 |
|---|---|
| 정체성 | experiment_id, hypothesis_id, owner, created/observed_at, source/code/config hash |
| 비교 대상 | baseline_stack_id 및 manifest/prediction hash, candidate hash, 실제 결합 수식·target별 멤버 |
| 평가 계약 | study UID/hash·target 순서·label/mask/split/group/transform hash·OOF 생성방식·ancestor 노출 상태 |
| 결과 | 같은 계약의 baseline/candidate/결합 Δ, 12소견 P/N·Δ·조건부CI·skip·그룹별 진단, 실행시간/RAM |
| 해석 | weak개발/Gold노출/독립/누출/미확인 구분, 기각 범위, 재검토 조건, 증거 URI |

‘현재 best보다 +0.001’ 대신 ‘기준 스택 X의 hash H, 계약 C에서 +0.001’로 기록한다. 기준이 바뀌면 옛 결과를 새 스택에 대한 주장으로 재사용하지 않는다. 낮은 상관은 후보 선별 단서일 뿐이고, 보완 효과는 고정 결합의 paired 비교로 측정한다. 글의 AUC>0.94/상관<0.99는 해당 대회의 경험칙이라 Knee 채택선으로 옮기지 않는다.

## 5. 새 모델링 기법 중 먼저 시험할 후보

**CPU 소형 probe: 조건부 추천.** 이미 저장된 test에서도 얻을 수 있는 시리즈 가용성·영상 수/간격·coverage/결측 같은 메타데이터를 소수 묶음으로 고정해, 간단한 정규화 logistic regression 또는 작은 트리를 검토할 수 있다. DICOM 전체 재디코딩이나 새 image backbone 학습을 먼저 할 필요는 없다. 무엇이 실제 저장돼 있고 test에서도 같은 정의인지 먼저 확인한다.

- 입력에서 Report, 라벨 생성 흔적, StudyUID/환자 식별자, 목표값에 의존한 특징을 제외한다. scanner/protocol 특징도 기관·라벨 생성 방식의 편향을 학습할 수 있어 그룹별 전이를 확인한다.
- 전처리·결측 대체·특징 선택을 train fold에서만 fit하고, 같은 validation UID의 작은 모델 예측과 사용 가능한 기준 예측을 결합한다. 사전 고정 가설·결합법·소수 후보로 제한하며 LB를 특징 선택에 쓰지 않는다.
- 기존 B/RN weak개발 계약에서 선별하면 **그 계약의 개발 결과**로만 기록한다. anchor가 V를 보았으면 anchor 개선의 독립 증거로 쓰지 않는다.
- 후보별 P/N·소견 손실·group 차이와 비용을 함께 본다. CPU 작업 상한은 우선30분 제안이며 실제 데이터 규모 확인 뒤 고정한다. 병렬작업은 기본12워커/내부스레드 합산 규칙을 적용하되 작은 회귀를 억지로12프로세스로 늘리지 않는다. 이번에 비용 측정·실험은 하지 않았다.
- probe 실패는 해당 메타데이터의 단독/고정결합에서 이득을 못 찾았다는 뜻이다. 영상과의 비선형 상호작용이나 coverage 개선 전체의 반증이 아니다. 양성 결과 역시 전체 영상 모델에 넣으면 그대로 좋아진다는 보장은 아니다.

**logit stacking: 후순위 조건부 후보.** 원리는 target별로 `logit(clip(p))`를 입력받는 정규화 회귀다. 작은 행렬은 CPU로 충분할 수 있어 cuML 도입부터 할 필요가 없다. 독립적이고 정렬된 예측이 확보되면 소수 모델부터 고정 rank/probability 평균과 비교한다.

그러나 base OOF에 stacker를 fit한 후 같은 행에서 점수를 재면 낙관적이다. 메타모델의 단순 cross-validation만으로도 충분하지 않을 수 있다. 평가 바깥 fold가 base/teacher 학습이나 특징·모델 선택에 흘러들지 않는 **전체 파이프라인의 outer 검증** 또는 공통 미사용 평가셋이 필요하다. 이미 노출된 Gold58이나 R2의 재분할로 해결되지 않는다. 기존 모든 모델의 누출 상태가 같다는 뜻도 아니다. 현재 자료로 할 수 있는 개발 비교와 독립 성능 주장을 구분한다.

60모델은 목표 수가 아니다. 기존 검토의 anchor+6은1300건 가정10.503h로9h를 넘었고, RN3 단독 비용은 아직 실측되지 않았다. [RN3 producer 기록](../handoffs/evidence/2026-10/2026-10-04-rn3-cost-v1/HANDOFF.md)은16:38 DEFERRED/INCOMPLETE다. 이는 실제 hidden건수/새조합 runtime을 확정한 결과가 아니며 이 조사에서 재개하지 않았다.

## 6. 그대로 가져오지 않을 것과 다음 순서

- `1-p`는 동일 이진 AUC에서 순서를 뒤집어 점수를 숨기는 방법이다. 성능 개선이 없고 제출 횟수를 쓰므로 우리 우선순위가 아니다.
- 전기차 표형 데이터의 생성 규칙/BPE 특징을 MRI에 직접 옮기지 않는다. 새 정보·잔차 기여를 싸게 선별한다는 원리만 검토한다.
- 원문의 no-pseudo-label 선택을 우리 Silver·teacher 전략 전체의 기각 근거로 삼지 않는다. 반대로 글의 CV 신뢰 권고도 노출된 weak CV를 임상/private의 대리 정답으로 만들지 않는다.
- 여러 AI의 합의나 표결을 증거로 세지 않는다. 다양한 가설 제안은 유용하지만 채택은 검증 계약·오류 기여·비용으로 한다.

권장 순서는 **기준스택을 명시한 인계·교차검토 → 완료한 동일계약 결과 재사용 → test가용 메타데이터 CPU probe 한 묶음 → 유망 후보만 GPU 확인**이다. 전체 과거 기록 재독·신규 다중 에이전트 시스템 구축은 선행조건이 아니다. 현재 실행 중인 연구 계획의 재개·변경은 그 담당자가 최신 상태를 회수해 판단한다.

전략 누락 점검: M02/03 검증노출과 그룹독립성, M04 작은양의효과/소견손실, M05 특정실패의 과잉일반화, M08 실행성/성능 분리, M10 기준본 전이공백을 적용했다. 이번 추가 근거는 S6E9 원문·댓글이며 기존 결론을 뒤집는 Knee 실험 결과는 없다. 성능 향상을 주장하지 않고 적용안을 남긴다.

AGENTS.md는 작업 규칙과 진입점만 유지하고, 각 기록의 원본 위치는 기존 handoff-maintenance.md의 책임표에서 정한다. CLAUDE.md는 공통 규칙의 진입 링크만 유지한다. HANDOFF에 누적 결정의 고정 요약/링크를 남기는 것은 의도된 짧은 안내이며, 상세 결과를 여러 곳에서 독립 갱신하는 것과 구분한다.
