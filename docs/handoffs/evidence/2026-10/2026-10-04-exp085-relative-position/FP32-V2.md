# EXP085 V2 · autocast 경계 수정

2026-10-04 03:00 KST. V1은 CPU 초안이며 pilot/GPU 실행은 없었다. 원본 실패 실행을 새로 만들어내거나 이전 근거를 덮어쓰지 않는다. [V1 snapshot manifest](v1-snapshot/snapshot-manifest.json)에 source·runner·tests·manifest·당시 문서10개를 SHA와 함께 보존했다. 기존 V1 protocol 파일도 그대로다.

문제: 바깥 autocast가 활성화되면 `torch.matmul(q.float(),k.float())`도 reduced precision으로 실행할 수 있다. 보존된 V1 helper를 CPU bfloat16 autocast에서 실제 실행한 합성 반례에서 qk와 value matmul 결과가 모두 bfloat16이었다. 이 반례는 실제 모델/GPU 학습 실패가 아니다.

수정: logits 계산부터 softmax·value 합산까지 `torch.autocast(device_type=features.device.type, enabled=False)`로 감쌌다. qkv·relative MLP·projection은 원래의 바깥 autocast 정책을 유지한다. residual만 원 feature dtype으로 복원한다. 파라미터·구조·loss·epoch·학습률·예산은 그대로다.

[CPU52검사](verification-v2.json)는 바깥 CPU bfloat16 autocast를 켠 채 **실제 두 matmul 결과**를 가로채 FP32이고 각 연산 동안 autocast가 꺼져 있음을 확인했다. logits/attention/context도 FP32, qkv/projection은 bfloat16, 결과·gradient는 유한하다. valid/all-invalid 두 경우를 검사했다. CUDA 초기화는 false다.

실제 첫batch gate도 `verify_initial_forward`로 보완했다. eval/train 각각 원 B와 확장 B의 logits, RNG 소비량, buffer update를 비교한다. 각 probe 전에 같은 RNG/buffer로 복구하고 전체 검사 후 원래 RNG/buffer/mode를 복구한다. BatchNorm+dropout 합성 모델에서 성공했고 출력이 같아도 추가 RNG를 소비하면 실패하는 반례를 검사했다. 실제 GPU 첫batch 검사는 앞으로 pilot에서 수행된다.
