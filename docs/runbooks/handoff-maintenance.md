# 문서 작성·인계·보관 규격

2026-10-05 사용자 지시 적용. 전체 규칙은 [AGENTS](../../AGENTS.md), 이 문서는 작성 형식과 유지 절차의 원본이다. [변경 전 원문/hash](../handoffs/archive/snapshots/2026-10-05-agent-rules-v2/manifest.json).

## 적용 범위와 문서 책임

최신 사용자 요청·승인이 기존 문서보다 우선한다. AGENTS는 공통 지시, runbook은 세부 절차, ADR은 해당 주제의 결정 근거다. 현황 문서는 새 권한을 부여하지 않는다. 과거 문서와 현재 지시가 다르면 적용 날짜와 대체 관계를 표시한다.

| 문서 | 관리할 정보 | 읽는 범위·크기 |
|---|---|---|
| AGENTS.md | 전체 지시·역할·권한·읽기 순서·공통 규칙 | 항상, 최대 2500자 |
| CLAUDE.md | AGENTS를 읽으라는 한 줄 | 별도 규칙 없음 |
| HANDOFF.md | 실제 진행·결과·담당·ID·로그·재개·예약 | 항상, 최대 2000자/50줄 |
| plan.md | 다음 가설·우선순위·예산·검증/중단/채택 조건 | 관련 항목, 완료 결과는 HANDOFF 링크 |
| discoveries.md | 배운 점·실패 범위·closed ideas·재검토 조건 | 요약·색인 먼저, 관련 ID만 상세 읽기 |
| docs/STATE.md | 구현·데이터 참고 사실 | 필요할 때, 최대 2500자 |
| 날짜별 인계 | 한 작업의 결과·근거·미해결·재개 | 최대 2000자/50줄, 긴 근거는 evidence |
| INDEX/월별 목록 | 최근/전체 기록의 위치 | INDEX 최근 10건/2500자, 월별은 이력 |
| runbook/ADR | 실행 절차·예외·설계 근거 | 해당 작업 부분만 |

같은 현재 점수·ETA·우선순위를 여러 문서에서 독립 갱신하지 않는다. 요약·색인은 원본으로 연결하며 별도 progress.md는 만들지 않는다. README는 진입점, CLAUDE는 AGENTS 안내만 유지한다.

## 공통 작성 형식

- UTF-8, BOM 없음, 새 파일·수정 영역은 LF 줄바꿈과 마지막 개행을 사용한다. 크기는 줄바꿈을 LF로 정규화한 문자 수(공백·개행 포함)와 `splitlines()`의 줄 수로 센다. 길이를 줄이려고 띄어쓰기나 조건을 생략하지 않는다.
- 문서당 `# 제목` 하나, 구획은 `##`, 개별 항목은 필요할 때 `###`를 사용한다. 제목·문단·목록·표·코드 블록 사이에 빈 줄을 두고 표의 헤더/구분선/행 사이에는 빈 줄을 넣지 않는다.
- 한 항목에는 한 규칙이나 사실을 적는다. 병렬 정보는 목록/짧은 표, 긴 근거는 링크를 사용한다. 명령·경로·ID는 backtick, 프로젝트 문서 링크는 상대 경로를 사용한다.
- 시각은 `YYYY-MM-DD HH:mm KST`, 기계 기록은 timezone이 포함된 ISO 8601이다. 현재 상태 문서의 갱신 시각과 과거 결과의 관측 시각을 구분한다. 날짜·added_at·실험ID·교훈 ID를 문서 정리 때문에 바꾸지 않는다.
- 상태는 진행/완료/실패/보류/차단을 사용한다. 기존 도구의 상태값은 그대로 인용한다. 사실·해석·계획·미확인을 구분하고, 프로세스 종료·정적 검토·독립 재현·성능 향상을 섞지 않는다.
- HANDOFF는 `현재 작업 → 결과·보류 → 재개·예약`, plan은 `우선순위 → 실험 계약 → 기록 형식`, discoveries는 `요약·색인 → Closed ideas → 교훈 상세` 순서다. 제목만 맞추기 위해 빈 내용이나 사실을 만들지 않는다.

## 내용별 작성 틀

- 인계: [TEMPLATE](../handoffs/TEMPLATE.md)의 상태/담당 → 요청/결과 → 검증/한계 → 다음/재개 순서를 사용한다. 작은 변경은 기존 기록에 3~5줄로 합친다.
- 계획: `ID·우선순위 / 가설·새 근거 / 변경 변수·고정 평가 계약 / 담당·검토 단계 / 재사용 결과 / 예산·중단·채택 조건 / 결과 링크`. 계획 변경 시 갱신하고 완료 결과를 누적하지 않는다.
- 교훈: `ID·주제 / 관측·판단 / 적용 범위·반복 금지 / 재검토 조건 / 근거`. 특정 설정의 실패를 전략 전체의 실패로 확대하지 않는다. 기존 M/D ID는 유지하며 새 ID는 중복 없이 부여한다. Closed ideas는 요약 색인이고 상세 항목이 원본이다.
- 도구: `목적·적용 범위 / 입력·출력 / 실행 예시 / 실패·제한 / 근거`. 기존 도구 확장을 우선하며 비용 대비 이득이 없는 일회 작업을 억지로 도구로 만들지 않는다.

## 갱신과 인계 절차

- 실제 작업 시작·완료/실패·주요 결정·범위/예약 변경·다른 담당자에게 인계할 때 HANDOFF를 갱신한다. 정기 체크포인트는 폐지한다. 변화가 없으면 확인 시각만 바꾸거나 기록을 위해 조회·예약하지 않는다.
- 새 교훈이 없는 단순 질문·읽기 전용 검토는 답변으로 끝낼 수 있다. 재사용할 교훈·중요 정정이 생기면 아래 discoveries 절차를 따른다. 사용자가 변경 금지를 요청하면 기록 파일도 수정하지 않는다. 코드/문서 변경이나 실행·결정이 있으면 결과를 기록한다.
- 실행/재개 전 해당 담당·PID/명령·원격ID·로그·receipt·산출물·예약을 대조한다. 기록이 오래됐다는 이유만으로 담당 부재나 작업 종료를 추정하지 않는다. 유효 완료 결과는 재사용하고 실패/부분 결과는 보존한다.
- 조정자 한 명이 중앙 문서를 병합한다. 자식은 할당 파일과 근거·실제 검사·미확인 사항을 반환한다. 편집 직전에 최신 파일을 확인한다. CLI 자체 잠금은 외부 세션까지 통제하는 전역 잠금이 아니다.
- 긴 작업은 실제 ID·로그·ETA·허가된 후속·중단/재개 명령·예약 결과를 남긴다. 완료 확인 예약은 [도구 절차](tools.md)를 따른다. 예약 도구가 없거나 실패하면 자동 재개를 보장하지 않고 해당 상태를 명시한다.
- 계획은 plan, 교훈은 discoveries, 구현/데이터 사실은 STATE에만 갱신한다. 새 인계는 INDEX와 월별 목록에 연결한다. 종료 전 문서 검사 도구로 크기/형식/링크를 확인하고 바뀐 문서만 API/Store에 반영해 added_at을 보존한다.

## discoveries 갱신

- 실험 결과, 문헌·공유 노트북 조사, 중요한 판단 변경, 사용자 지적에 따른 정정에서 재사용할 교훈이 생기면 답변·인계 전에 기록한다. 변화 없는 진행 조회마다 새 항목을 만들지 않는다.
- 관련 기존 M/D ID를 먼저 갱신하고 별개의 교훈만 새 ID를 부여한다. `관측·판단 / 적용 범위·반복 금지 / 재검토 조건 / 근거`를 남기며 요약·색인을 함께 맞춘다. Closed ideas는 실제 보류·기각 범위가 바뀐 경우에만 상세 항목과 맞춘다.
- 외부 작성자의 주장, 우리 실험의 관측, 운영 제안을 구분한다. 출처·revision/hash·관측 시각을 가진 원근거로 연결하고 미확인을 남긴다. 문헌 수치를 Knee의 기대 개선량으로 옮기거나 구현 실패·부분 실행을 성능 실패/성공으로 기록하지 않는다.
- 전략 교훈은 정제·재학습 범위와 개발 비용·제출 추론 비용을 구분한다. 새 교훈이 없는 기존 결과·동일 감사는 재사용한다. 다음 실행·예산은 plan, 실제 진행은 HANDOFF에만 두며 문서 기록 자체를 연구 재개·추가 학습 승인으로 해석하지 않는다.
- 문서 담당자가 종료 전 누락·색인·근거 링크와 문서 검사 결과를 확인한다. 다른 담당자의 진행·예약을 덮어쓰지 않고 기존 ID·원문·added_at을 보존한다.

## 압축과 보관

- 요약/이동 전 원 bytes를 archive/snapshots에 보존한다. manifest에 원래/보관 경로·SHA256·bytes·관측 시각을 기록하고 hash를 확인한다. 원문은 `.md.txt` 등으로 보존해 일반 Markdown 수집 중복을 피한다.
- 사용자 조건/승인·최종 결과·출처/revision/hash·평가 계약·불확실성·실패/복구·미해결·재개 근거를 보존한다. 철회된 의심을 사실로 되살리거나 실패를 성공으로 덮지 않는다.
- 7일 또는 신규 10건 중 먼저 도달할 때 작업 중 보관을 점검한다. 최근 30일·최신 5건·미완료 근거를 유지한다. 기록만을 위한 예약은 만들지 않는다.
- 상한을 넘으면 원문 보존 후 완료 이력을 상세 기록으로 분리하고 요약·링크를 남긴다. 이동 전 절대 경로가 의도한 영역 안인지 확인한다. 원본 데이터·모델·runtime DB는 정리 대상이 아니다.
