# MRI 영상 분석 사용법

주소: `http://127.0.0.1:8765/#viewer`. 왼쪽 **학습 데이터 → 영상 분석**에서 연다. 서버는 이 PC의 localhost에서만 실행하고, 영상은 외부에 전송하지 않는다. 원본·캐시·라벨 CSV는 읽기 전용이다. 검토 메모만 개인 SQLite DB에 저장한다.

## 첫 영상 열기

1. 왼쪽 **폴더 구조**에서 전체 원본 ZIP → train_series/test_series → study → 시리즈 → DICOM을 펼친다. 파일을 누르면 물리 정렬상 해당 슬라이스로 바로 이동한다. 캐시는 전처리 캐시 → 캐시 이름 → study → slot → 슬라이스 순서다. 실제 로컬 폴더도 펼칠 수 있다.
2. UID 검색·결측/불완전 원본·공식 라벨·양성 소견 필터를 사용한다. study는 40개, ZIP 시리즈의 파일은 30개씩 표시한다. **목록 보기**로 이전 목록 UI를 사용할 수 있다. 전체 데이터 EDA는 탐색 필터와 무관한 전체 메타데이터 집계다.
3. study를 선택하고 AX_FS/SAG_FS/COR_FS/SAG_STRUCT 등 시리즈를 전환한다. 캐시별 slot 명칭과 유효 슬라이스 수를 표시한다.

내려받은 원본은 **다운로드·캐시 → 로컬 원본 데이터 → 영상 열기**, 또는 영상 분석의 데이터 선택에서 **내려받은 원본 DICOM**으로 연다. 로컬 목록을 먼저 새로고침한다. 테스트/일부 다운로드 경고와 누락 수를 표시한다. 등록된 전체 ZIP은 목록을 읽고 선택한 study만 lossless 해제한다. 폴더 펼치기는 압축을 해제하지 않는다.

**로컬 파일·폴더 열기**를 펼치면 전체 경로 또는 workspace 기준 경로를 직접 입력할 수 있다. 아래 프로젝트 데이터 탐색에서는 원본·캐시·다운로드 폴더 등을 한 단계씩 열 수 있다. DICOM은 최상위 전체 데이터 폴더 대신 한 study 폴더를 선택한다. 임의의 다른 로컬 디스크 파일도 경로로 열 수 있지만 네트워크 공유 경로는 지원하지 않는다. 경로 입력은 localhost 쓰기 토큰 검사를 거친다.

| 형식 | 지원 범위 |
|---|---|
| 캐시 manifest JSON | 기존 Adjacent/Orthodiffusion의 uint8 `[study,slot,slice,H,W]` shard + UID + 유효 mask |
| 단독 NPY | 숫자형 `[H,W]`, `[Z,H,W]`. pickle/object 배열 불가. 해부학적 방향·UID를 추정하지 않음 |
| DICOM | 단일 프레임 흑백 파일 또는 한 study의 시리즈 폴더. JPEG/JPEG-LS/JPEG2000/RLE 등 설치된 decoder 사용 |
| 공식 전체 ZIP | 인덱스된 원본 트리에서 study 단위로 준비·열기. 직접 경로 ZIP 열기는 미지원 |
| NPZ/NIfTI/Zarr/다중 프레임 DICOM | 현재 미지원. 5차원 NPY shard는 manifest로 열기 |

## 탐색·측정·분석

- **슬라이스**: 하단 슬라이더/이전·다음/유효 마스크 막대, 영상 위 휠, 캔버스 포커스에서 ←/→. 재생은 250ms 간격(목표 4fps)이며 현재 프레임이 준비되었을 때만 이동한다. 다음 영상은 디코딩 완료 뒤 교체하고 기존 영상을 유지한다. 캔버스의 #번호가 실제 표시 장이며, 슬라이더는 요청 위치다. 700ms 이상 기다릴 때만 작은 준비 안내를 표시한다.
- **대비**: 밝기 최소/최대는 표시 창의 하한/상한이다. 직접 입력하면 슬라이스 간 고정한다. 자동은 캐시 0–255, DICOM/단독 NPY는 매 슬라이스의 1–99 percentile이다. 흑백 반전 가능. 원본 픽셀을 바꾸지 않는다.
- **이동·확대**: 이동 도구에서 드래그. +/- 또는 Ctrl+휠, 맞춤으로 복원.
- **ROI**: 영역 선택 도구에서 직사각형 드래그. 최소/최대, 평균, 표준편차, 히스토그램, 0 값 비율을 확인한다. NaN/Inf는 통계에서 제외하고 개수를 안내한다. ROI는 슬라이스를 바꿔도 같은 정규화된 위치를 유지하므로 비교할 수 있다. 시리즈 변경은 초기화한다.
- **길이**: 길이 도구로 두 점을 드래그한다. DICOM PixelSpacing이 해당 시리즈에서 일관되게 확인되면 mm, 그렇지 않으면 px. ROI 면적도 동일 조건에서 mm²를 제공한다. 캐시는 resize/crop 후 실제 간격이 보장되지 않아 px만 표시한다. 길이 선은 화면에서만 유지한다.
- **모아보기**: 전체 범위에서 균등 간격으로 최대 12장을 가져온다. 각 이미지를 누르면 해당 슬라이스로 이동한다. 전체 영상 검사가 아니며 DICOM 자동 대비는 장마다 다를 수 있다.
- **현재 PNG**: 현재 표시 대비를 반영한 한 장을 저장한다. ROI/길이 선은 PNG에 포함되지 않는다. ROI 좌표·통계는 검토 JSON을 사용한다.

DICOM은 IOP/IPP 법선 투영으로 정렬한다. 기하 정보가 불완전하거나 방향이 일치하지 않으면 InstanceNumber와 파일명으로 정렬하고 경고한다. 위치 중복·간격 불균일·픽셀 간격 불일치도 기록한다. RescaleSlope/Intercept와 MONOCHROME1을 반영한다. MRI 강도는 HU가 아니다. 저장 방향을 그대로 보여주며 자동 재방향, 좌우 라벨 추정, 시리즈 간 위치 동기화, 3D/MPR 재구성은 하지 않는다.

## 라벨·판독문·검토 기록

공식 `train.csv`/`test.csv`를 StudyInstanceUID로 연결한다. workspace의 원본 CSV가 있으면 우선하고 없으면 설정된 다운로드 폴더를 사용한다. 0/1만 공식 음성/양성으로 표시하고 나머지는 미표기다. 서드파티 LLM 라벨과 자동 혼합하지 않는다. 현재 라벨이 있는 58 study는 이전 실험에 노출된 Gold58이므로 새로운 독립 holdout으로 취급하면 안 된다. 학습 Report는 펼쳐 읽는다. 테스트 Report는 표시하지 않으며 추론에 사용할 수 없다.

유효 mask가 0인 슬라이스는 경고하고 ROI 분석을 제공하지 않는다. 검은 영상이라는 이유만으로 결측으로 단정하지 않는다. 값의 분포/움직임/잘림 여부는 사용자가 직접 확인하고 기록한다.

메모와 확인 완료/움직임/잘림/결측/라벨 재검토 flag를 선택하고 **검토 기록 저장**을 누른다. source URI·study UID·시리즈·슬라이스·파일 버전 서명·manifest SHA256·픽셀 SHA256·ROI·표시 범위·메모를 저장한다. 같은 소스 버전의 같은 슬라이스를 다시 저장하면 메모를 갱신한다. 다른 파일 버전은 별도 기록으로 유지한다. 이전 파일 버전 기록은 현재 영상으로 이동하지 않는다. 전체 파일 SHA 검증 대신 경로·크기·mtime 서명으로 변경을 감지하며 캐시 전체 hash 검증을 의미하지 않는다.

현재 study의 최신 100개 검토 기록을 화면과 **검토 JSON**에서 확인한다. 화면에서 기록을 선택하면 같은 버전의 슬라이스·ROI·표시 범위를 다시 연다. 기록은 `.local/kneeops/app.sqlite`의 `viewer_reviews` 테이블에 있으며 전체 DB 백업에 포함된다. JSON에는 학습 Report나 이미지 본문을 넣지 않는다. 영상 세션은 메모리의 최근 24개이며 앱 재시작/오래된 세션 교체 후 다시 열어야 한다. 검토 메모는 남는다.

## 성능과 한계

NPY shard는 mmap 읽기 전용으로 열고 선택한 슬라이스만 복사한다. DICOM도 전체 볼륨 대신 현재 한 장을 decode한다. 이미지 한 장 4,194,304 픽셀, DICOM 파일 하나 64 MiB, study 폴더 300개·2,500 DICOM, NPY 4,096장까지 지원한다. 모아보기는 최대 12장이며 RGB/다중 프레임은 지원하지 않는다. 매우 큰 로컬 폴더는 한 단계에 5,000개 항목까지만 검사하고 지원 항목 최대 500개를 표시한다.

Docker에서도 같은 기능을 제공하지만 입력 경로는 `/workspace/...` 또는 `/downloads/...`처럼 컨테이너 안의 경로다. 호스트의 다른 드라이브는 읽기 전용 bind mount를 별도로 설정해야 한다. GPU/PyTorch는 설치하지 않는다.

이 기능은 데이터 품질 점검과 연구용이다. 병변 검출·분할·모델 예측·자동 진단은 포함하지 않는다. 실제 캐시와 대회 테스트 DICOM 두 시리즈(960×960, 800×800)의 표시를 확인했고 정렬/해독의 경계 조건은 합성 fixture로 검증했다. 현재 전체 ZIP에는 학습 4,407·공개 테스트 3 study가 인덱싱되어 있고 5 study의 815 DICOM이 준비되어 있다. 20~50 study의 체계적 내용 검토는 후속 작업이다.

## 전체 현황·품질 검사·비교 EDA

- **전체 데이터 EDA**: 학습/공개 테스트 study·시리즈·파일 수, 준비된 원본 범위, 12소견 양성/음성/미표기와 알려진 라벨 내 양성률, 동시 양성/두 라벨 관측 수 행렬, 촬영 방향과 수분 민감도·지방억제 분포, study당 시리즈·파일 분포를 제공한다. 소견 이름을 누르면 탐색의 양성 필터를 적용한다.
- **촬영 누락·정합성**: CSV에 특정 방향이 없는 study 예시(최대30), 중복 study 행, train/test Study UID 교집합, study CSV에 없는 시리즈, 인덱스에 없는 원본을 표시한다. 방향 부재 자체는 파일 손상 판정이 아니다. Study UID 교집합 검사는 환자 단위 누출 검증이 아니다.
- **캐시 범위**: 공식 train UID 누락/추가, 결측 포함 study, slot 전체 결측과 슬라이스 마스크 결측을 비교한다. 전체 픽셀 품질은 검사하지 않는다.
- **시리즈 품질·촬영 정보**: 해상도·픽셀 간격·두께·TR/TE·자기장·flip angle을 보여준다. 촬영 파라미터는 시리즈 첫 DICOM의 대표값이다. 검사 버튼은 8/16/32/64장 균등 표본의 평균·표준편차·0비율·NaN/Inf·균일 영상·동일 픽셀 후보, 참고 경계 에너지와 연속 표본 간 변화량을 계산한다. 그래프/표에서 해당 장으로 이동하고 점검 후보만 볼 수 있다. 물리 위치가 있으면 촬영 범위·FOV·중복 위치·간격 불균일을 제공한다. 표본 공통 1–99% 대비를 적용할 수 있다.
- **같은 study 비교**: Study UID가 같은 원본과 두 캐시를 나란히 연다. 확인 가능한 방향을 참고해 초기 비교 시리즈를 선택하며 사용자가 변경할 수 있다. 상대 슬라이스 위치 맞춤은 비율 기반 이동이며 해부학적 정합이 아니다. 원본/캐시 강도·해상도 차이만으로 학습 성능을 추정하지 않는다.
- **전처리 미리보기**: 현재 한 장에서 128/224/256/288/336/384/512 해상도, 중앙 crop 25~100%, minmax/1–99/2–98% 정규화를 비교한다. 종횡비를 유지하는 bilinear resize와 검은 padding을 적용한다. 면적 보존율·crop FOV·입력 배열 bytes·확대 여부를 제공하며 원본·학습 설정은 바꾸지 않는다. 변환 PNG·JSON을 내려받을 수 있다.

EDA JSON은 관측 시각·범위·CSV/manifest hash·원본 인덱스 revision 또는 선택 영상 revision/pixel hash를 보존한다. Report 본문이나 환자 DICOM 헤더 전체는 내보내지 않는다. 자동 병변 판정, 움직임 진단, 3D/MPR, 전체 원본의 픽셀 일괄 감사는 제공하지 않는다.

### 슬라이스 표시 버퍼

브라우저 메모리에서 인접 +1/-1/+2/+3/-2/+4 장을 미리 읽고 PNG 디코딩까지 완료한다. 최대24장·추정32MiB, 15초 TTL이며 study/시리즈/ROI/표시 범위/반전 변경 때 초기화한다. 디스크 학습 캐시와 별개이며 파일을 생성하지 않는다. 열린 study의 트리에서 다른 DICOM을 누를 때 기존 세션을 재사용하여 헤더 재스캔을 생략한다.

버퍼 프레임은 최대15초 동안 원본 변경을 다시 확인하지 않는다. 새 서버 읽기와 검토 저장은 기존 파일 서명을 검사한다. 파일을 교체했다면 **study 영상 열기**로 새 세션을 연다. 느린 디스크의 최초 열기나 아직 준비되지 않은 먼 슬라이스로 이동할 때 실제 읽기 대기는 남을 수 있지만 이전 영상을 지우지 않는다. 이때 표시 #번호로 실제 장을 구분하고 새 프레임이 준비되기 전에는 측정/검토 저장을 비활성화한다.

## AI·개발자 인터페이스

`monitoring/kneeops/viewer.py`가 파일 읽기/통계/검토 저장, `viewer_api.py`가 입력 검증과 HTTP 경계를 담당한다. UI와 같은 로컬 API를 사용한다. `GET /api/session`의 token을 POST의 `X-Kneeops-Token`에 넣는다. 원격 주소를 사용하지 않는다.

- `GET /api/viewer/catalog`: 지원 캐시와 탐색 roots, 인덱스된 raw study 목록.
- `GET /api/viewer/browse?root=...&relative=...`: 등록 root 안 한 단계 목록.
- `GET /api/viewer/studies?source=...&q=...&mode=all|missing|labeled&target=ACL&offset=0`: 목록과 캐시 전체 요약.
- `POST /api/viewer/open`: `{source,uid}` 또는 `{path}` 또는 `{raw: inventory_id}`. session ID·series·공식 metadata 반환. 원본 목록은 studies API의 `source=raw`로 검색한다.
- `POST /api/viewer/frame`: `{session,slot,slice,low?,high?,invert?,roi?}`. ROI는 `[x0,y0,x1,y1]`의 0~1 좌표. PNG data URI와 통계 반환.
- `GET /api/viewer/tree/series?source=<cache-id>&uid=...`: 픽셀 없이 slot·마스크 목록. studies API는 원본 `split=train|test`와 `root=<archive-id|root-URI>` 필터도 제공한다.
- `GET /api/viewer/eda/dataset`: 전체 메타데이터 EDA JSON.
- `POST /api/viewer/eda/series`: `{session,slot,samples:16}`. API 표본 한도3~64장.
- `POST /api/viewer/eda/preview`: `{session,slot,slice,resolution:288,crop_percent:100,normalization:"p1"}`.
- `GET /api/viewer/contact?session=...&slot=0`: 최대 12장.
- `POST /api/viewer/reviews`: frame 필드에 `note`, `flags` 추가.
